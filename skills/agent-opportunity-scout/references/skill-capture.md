# Skill Capture Scout

## Action Policy

Propose capture through the active runtime's skill-creation workflow. Do not hand-author a large skill from scratch when a dedicated skill creator or local convention exists.

## Recognition

Use this scout when all three are true:

- Recurrence is plausible across this project or future projects.
- The knowledge is non-obvious; a fresh agent would have to rediscover the failure modes or exact sequence.
- The lesson is procedural: it contains a repeatable "how", not just a fact.

Signals:

- A working pipeline emerged after several failed attempts.
- The user corrected the agent the same way more than once.
- A prompt, parameter set, environment setup, or tool workaround was tuned through iteration.
- The user says "remember this", "save this approach", "make this a skill", or asks how it was done.

## Stay Quiet When

- The lesson is a one-off trick.
- Existing skills already cover it; propose updating the existing skill instead.
- The content is only a preference or fact; that belongs in memory or project docs.

## Proposal Template

```text
We just built a repeatable technique: [what]. A fresh agent would need to rediscover [hard-won detail]. Worth capturing as a skill? Suggested name: [name].
```
